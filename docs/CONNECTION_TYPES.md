# 连接类型与端口

当前正式发行版本为 9.0.0；本开发分支正在实现 10.0.0。下文四步发布向导属于开发版，正式包以其实际界面为准。界面按服务端能力和账号权限开放连接；升级时请按对应版本的升级说明同步更新各端。

## 发布本机服务

1. **设备和服务模板**：Windows 客户端默认发布当前已登录、已登记设备上的服务，选择模板并命名。Web/Android 管理已授权设备。
2. **本地目标**：填写主机名或 IP、端口及适用的 HTTP/HTTPS 协议，然后检查目标。目标修改后须重新检查。
3. **访问方式**：核对域名或服务器分配的端口，以及当前账号可用的访问保护设置。
4. **核对并发布**：确认配置后创建，复制服务器实际返回的地址。界面区分创建成功、等待设备同步、配置已应用、暂停和错误；创建失败保留草稿。

本地检查和配置同步均不代表公网访问已经验证。创建后还需从外部网络使用目标应用检查实际地址、认证和传输。

## 服务模板

11 个模板为 HTTP、HTTPS、NAS、Home Assistant、Immich、Jellyfin、SSH、RDP、RTSP、通用 TCP 和通用 UDP。模板提供常用目标参数，实际端口仍以应用配置为准。

| 类型 | 底层传输 | 常见本地端口 | 使用方式 |
| --- | --- | --- | --- |
| HTTP / HTTPS | HTTP 网关 | 8080 / 443 等 | 选择目标服务的 HTTP 或 HTTPS 协议，使用分配的 HTTPS 公网域名 |
| NAS | HTTP 网关 | 5000 等 | 填写 NAS 的局域网地址，按实际配置选择协议和端口 |
| Home Assistant | HTTP 网关 | 8123 | 发布已配置好认证和反向代理信任的实例 |
| Immich | HTTP 网关 | 2283 | 发布相册服务，保留应用自身认证 |
| Jellyfin | HTTP 网关 | 8096 | 发布媒体服务，检查应用的远程访问和认证设置 |
| RTSP 摄像头 | TCP | 554 | 在播放器中启用 RTSP over TCP，给分配的地址补上摄像头流路径 |
| SSH | TCP | 22 | 使用分配的公网主机和端口连接 SSH |
| 远程桌面 RDP | TCP | 3389 | 在远程桌面客户端填写公网主机和端口 |
| 通用 TCP | TCP | 按应用填写 | 转发数据库、MQTT、游戏服务等 TCP 通信 |
| 通用 UDP | UDP | 按应用填写 | 转发使用固定端口的 UDP 服务 |

本地目标相对于运行客户端的这台机器填写。摄像头、NAS 等设备在局域网另一台机器上时，填写它的局域网 IP；`127.0.0.1` 表示运行客户端的电脑本身。

## 目标检查的范围

- TCP 检查目标端口能否接受连接，不验证应用认证。
- HTTP/HTTPS 先检查端口，再发送不带认证信息的 HEAD 请求；不使用环境代理、不跟随重定向，HTTPS 校验证书。401/403 等响应说明服务有响应，仍需在应用中验证授权。5xx 显示健康警告，继续前需明确确认。
- 端口不可达、HTTP 请求失败或 TLS 校验失败会阻止进入下一步。检查服务监听地址、协议和证书后重试；单次探测限时三秒。
- UDP 必须用对应应用从外部网络验证。打开 UDP 套接字不能证明可达，向导会要求明确确认这项限制。

主机字段只接受主机名或 IP，不填写 URL、用户名、密码或路径。修改目标、切换模板或离开检查步骤会使旧检查结果失效。

## RTSP

创建 RTSP 连接后会显示 `rtsp://公网主机:分配端口`。例如摄像头的流路径为 `/Streaming/Channels/101`，完整地址就是：

```text
rtsp://公网主机:分配端口/Streaming/Channels/101
```

在播放器中选择 **RTSP over TCP / interleaved**。例如使用 ffplay：

```sh
ffplay -rtsp_transport tcp 'rtsp://公网主机:分配端口/摄像头流路径'
```

此预设将 RTSP 控制和媒体放在同一条 TCP 连接中。使用动态 RTP/RTCP UDP 端口的模式还涉及端口和地址协商，不能靠单条 TCP 映射自动完成。摄像头的认证信息在播放器中配置。

## 公网端口和权限

TCP/UDP 公网端口由服务端从管理员已开放的范围内自动分配，客户端不能任意占用服务器端口。创建前会检查服务器能力、传输是否开启和账号权限；没有可用端口时会明确报错。

管理员可在自己的设备上创建连接。普通用户需要管理员在 Web 控制台“系统设置”中启用“允许普通用户自行创建 TCP/UDP 连接”。此设置只影响新建权限，已有连接仍可以编辑、停用和删除。

开启自助创建前，管理员还需配置对应的 Docker Compose 端口范围和主机／云防火墙，见[服务端自托管指南](https://github.com/ZHanry/home-tunnel-server/blob/main/docs/SELF_HOSTING.md)。界面中的授权开关不会代替服务器端口配置。

TCP/UDP 是透明传输，目标应用负责认证与加密；Web 网关的 Basic Auth、Web 流量配额等功能不适用于这些原始传输。涉及动态端口、多个媒体通道或嵌入地址的应用，还需要应用侧配置。
