> 2026-09-22 设计修订：增加显式启用的自建公网模式，替代“外网只能通过 WireGuard 回家”的限制。默认仍为纯内网；本轮已实现配置、外围策略、设置与部署工具并完成本地验证，真实跨网门禁仍待执行。实际进度见 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。

# 一、项目概述

## 1.1 背景与目标

- 家庭内多台设备（Windows 台式机/笔记本、Linux 主机/NAS、信创整机）需要互相远程操作，也需要在外出、移动网络或另一家庭宽带下连接家中设备。
- 商用远控（ToDesk/向日葵/TeamViewer）依赖厂商公网服务器：隐私出户、限速收费、断外网不可用；RustDesk 公共服务器在国内也已受限。
- 目标：**连接基础设施自主管理、直连优先**的家庭远控。纯内网模式保持数据不出户；自建公网模式允许端到端加密的会话流量跨公网，直连成功时画面、键鼠和文件不经过中继；不依赖厂商账号和公共连接服务器。

| 目标 | 量化指标 |
| --- | --- |
| 可用性 | 原纯内网 IP/发现兼容入口保留但加密另验；公网模式拒绝未加密 IP 入口，ID 服务不可达时不承诺新建连接 |
| 性能 | 同网段 1080p ≥ 60fps、端到端延迟 ≤ 60ms |
| 覆盖 | Windows 10/11、主流 Linux、麒麟/统信（x86_64、aarch64）；龙芯为探索档 |
| 成本 | 纯内网复用 NAS/小主机；公网主机、域名与中继流量可能产生费用，不要求商业服务订阅 |
| 安全 | E2E 加密、服务器公钥校验和设备端认证；网络访问范围按模式限定，默认不启用公网 |
| 公网连接 | P2P 优先、中继兜底；按真实网络记录直连率和性能，不承诺跨运营商或任意 NAT 下 100% 直连 |

## 1.2 非目标（明确不做）

- 不做企业级多租户、组织架构、集中策略下发
- 2026-10-01 门户增量：HomeDesk 桌面首页显式接入自建 home-tunnel，提供账号所属设备/服务目录、服务创建/编辑/启停/删除及设备标签/收藏；Windows 支持系统加密的记住登录。不接管其原生远控协议或 FRP Agent，也不承担服务端运营者管理。
- 不做 iOS/macOS 客户端（家中无需求，架构上不排斥）
- 不经营公共穿透/中继服务，不承诺任意网络都能打洞；自建公网连接纳入独立阶段，WireGuard 保留为可选接入方式
- 本轮不开放公网 Console，不增加集中远控授权、云地址簿或新的强制“仅直连”产品开关
- 不自研视频编解码/传输协议（完全复用上游）

## 1.3 典型场景

1. 客厅笔记本（Windows）控制书房无头 Linux 主机改配置、跑脚本
2. 帮家人远程操作：卧室 Windows → 父母房间 Windows，直接看桌面带操作
3. 手机浏览器打开管理台看设备在线状态，WOL 唤醒书房主机再远控
4. 信创机（麒麟/UOS）作为被控端，被 Windows 主控端日常操作
5. 外出笔记本通过自建公网服务器撮合，与家中电脑优先 P2P 连接；打洞失败时由自建中继转发加密数据
6. 外网访问 Console、设备墙和 WOL 时先接入受控 VPN；无 VPN 时仍可通过设备 ID 或最近连接发起远控

# 三、开源选型

## 3.1 候选对比

| 维度 | RustDesk | MeshCentral | Apache Guacamole | 完全自研 |

## 3.2 结论

**选 RustDesk 全家桶（rustdesk 客户端 + rustdesk-server OSS）作底座**：

- 与目标场景（原生客户端、内网直连、高画质、无人值守、自托管）重合度最高，二开只做「减法 + 家庭壳」，不动传输/编解码核心
- hbbs（ID 注册/信令/打洞协调）+ hbbr（中继兜底）架构清晰、资源占用极低，1C1G 设备即可常驻
- 商业信创远控（ToDesk 信创版等）已验证「信创 + 远控」需求成立，但闭源收费；RustDesk 是同时满足「开源 + 原生客户端 + 自托管」的最成熟选择
- Guacamole 仅保留为应急旁路认知（浏览器 → 网关 → VNC/RDP），本项目不集成

## 3.3 AGPL-3.0 合规边界

| 场景 | 义务 |
| --- | --- |
| 家庭自用（不分发二进制） | 无开源义务，fork 仓库可私有 ✅ 本项目现状 |
| 把修改版二进制分发给他人 | 需按 AGPL 提供对应源码 |
| 用修改版对公众提供网络服务 | AGPL §13：需向服务使用者提供源码 |

→ 决策：仓库私有 + 仅家庭内使用；未来若外发，届时开源 fork 即可合规。

# 四、总体架构

## 4.1 组件视图

纯内网模式：

```
┌─ 家庭内网 192.168.1.0/24 ─────────────────────────────────┐
│                                                           │
│  服务端主机（NAS / N100 小主机，常开）                       │
│  ├─ hbbs    ID 注册 · 信令 · 打洞协调（上游，不改）           │
│  ├─ hbbr    中继兜底（上游，不改）                           │
│  └─ console 自研管理台：设备清单 · WOL · 审计（Rust+SQLite） │
│                                                           │
│  主控端 HomeDesk Client（Windows / Linux x64，Flutter UI）  │
│  被控端 HomeDesk Agent（全档平台，系统服务常驻）              │
└───────────────────────────────────────────────────────────┘
```

自建公网模式：

```text
外出客户端 ── 注册/信令 ── 自建公网 hbbs ── 注册/信令 ── 家庭客户端
     └──────────────── 加密 P2P 直连（优先） ─────────────────┘
     └──────── 自建 hbbr 转发加密数据（直连失败时） ──────────┘

家庭客户端 ── 心跳/会话上报 ── 家庭内网 Console
外出客户端/浏览器 ── 可选受控 VPN ── Console（设备墙/WOL/审计）
```

- 主控端 / 被控端是**同一个程序的两种角色**（沿用上游设计）；T3 档提供纯被控 no-GUI 形态
- console 与 hbbs/hbbr 完全解耦：console 挂了不影响远控本身
- hbbs 负责 ID 注册、在线心跳、信令和打洞协调；**远控密码由被控端校验**。服务器公钥校验、设备远控认证、Console 登录是三种独立职责，不把 hbbs 描述成集中账号认证服务。
- 公网 hbbs/hbbr 可部署在同一台自有公网主机，也可部署在具备公网可达条件的家庭主机；Console 无须随之迁移到公网。

## 4.2 端口规划

| 端口 | 协议 | 所在 | 用途 |
| --- | --- | --- | --- |
| 21115 | TCP | hbbs | NAT 类型测试 |
| 21116 | TCP + UDP | hbbs | ID 注册、心跳、信令与打洞协调；服务端 UDP 流量不等于会话使用 UDP |
| 21117 | TCP | hbbr | 中继数据 |
| 21118 / 21119 | TCP | hbbs / hbbr | WebSocket（仅 Web 客户端需要，默认关闭） |
| 21118 | TCP | 被控端 | IP 直连监听（可改端口） |
| 8080 | TCP | console | 管理台 Web（仅内网监听） |
| 9 | UDP | console → 广播 | WOL 魔术包 |

以上为默认端口，可达范围取决于模式：纯内网仅向家庭网络开放；公网模式对外开放所用 hbbs 的 TCP 21115、TCP/UDP 21116，以及兜底 hbbr 的 TCP 21117。不随之开放 Console 8080、WOL UDP 9、WebSocket 或被控端 IP 直连监听端口。客户端 NAT 打洞使用上游选择的端口与系统防火墙规则，不能用服务端端口清单代替客户端连通性验证。

## 4.3 连接建立流程（两种模式均直连优先）

1. 被控端服务启动，向当前模式配置的自建 hbbs 注册并保活；Console 上报独立进行，不能阻塞远控。
2. 主控端点击可用的设备条目、最近连接或输入 ID，hbbs 撮合双方；客户端沿用上游直连尝试和选择机制，不另写“先 IPv6、再 UDP、再 TCP”的固定顺序。
3. 直连建立后，由被控端完成密码校验或本地确认，建立经过验证的加密会话；画面、键鼠、文件在客户端之间传输。hbbs 仍可承担心跳和信令，不能宣称连接后服务器完全没有流量。
4. 直连失败时使用配置的自建 hbbr 兜底，仍要求端到端加密。中继不可达则明确报错，不回退到厂商公共服务器。TCP 直连同样属于 P2P，UDP 与 IPv6 路径按 4.5 的兼容性门禁启用。
5. 旁路一：**局域网 IP 直连**——仅原 `lan_only` 兼容入口，在网络与入站权限允许时输入设备私网 IP 绕过 hbbs；该上游路径未经过同等加密握手，不能把“连通”当作安全会话验收通过。`self_hosted` 拒绝此入口并指引使用设备 ID。
6. 旁路二：**局域网发现**——同网段发现设备后仍按其实际 ID/IP 连接路径实施对应校验；发现不能给 IP 连接豁免加密要求，广播也不能跨 NAT/VLAN 替代公网设备目录。

公网 ID 服务故障或断公网后，公网模式不承诺新建连接，不能自动降级成未加密 IP 连接；原纯内网 IP/发现兼容入口保留但不代表加密验收通过。切换到有效的私网服务器配置后可重新使用 ID 撮合；不承诺跨网连接或原会话在网络切换时无缝保持。首版保留自动中继兜底，不把关闭 hbbr 的诊断操作包装为已经实现的“仅直连”模式。

→ 排障原则：会话信息显示实际「直连/中继」和加密状态，详情记录实际传输类型或明确“未知”；模式名称或开关值不能代替连接结果。

## 4.4 网络模式与边界

| 策略 | 纯内网 `lan_only`（默认） | 自建公网 `self_hosted`（显式启用） |
| --- | --- | --- |
| 自建连接服务器 | 数字形式的 RFC1918 私网地址，禁止外部域名解析 | 配置的自建公网/私网 IP 或域名，必须有匹配公钥 |
| 出站范围 | 所需家庭私网服务、允许的局域网连接及发现 | 自建信令/中继、必要 DNS、经兼容性验证并明确配置的打洞服务、当前连接需要的对端地址，以及按 5.4 显式登录的 HTTPS 管理端点 |
| 入站来源 | 家庭 CIDR 白名单，并验证设备密码/本地确认 | 不再自动套用家庭 CIDR；允许经设备认证的跨网连接，可额外配置来源限制 |
| 直连与中继 | 内网直连优先，自建内网中继兜底 | 公网 P2P 优先，自建中继兜底 |
| 公共服务器回退、遥测、自动更新 | 禁用 | 禁用；启用公网远控不等于恢复全部上游公网行为 |
| Console | 仅家庭内网 | 仍仅家庭内网或受控 VPN，不因模式变化扩大开放范围 |
| 路由器/主机暴露 | 远控服务不做公网映射 | 仅开放自建连接服务所需端口；家庭设备无需逐台配置固定远控端口映射 |

约束：

- 公网模式对端地址会随 NAT、移动网络和 DNS 变化，不能把出站范围仅设成服务器 IP，否则会阻断 P2P；也不能放开所有 HTTP、下载和域名请求。新增逻辑在独立网络策略模块中集中实现，连接入口只做必要接线。
- 服务器地址、公钥、网络模式、来源限制和获准的打洞服务来自构建配置及受控高级设置。对地址导入、DNS 解析、服务端返回的中继/对端地址、代理、重定向和下载分别核验；不以收到服务器回包为由允许访问任意无关服务。
- 对端候选地址只从当前配置的信令服务器连接、当前待连接请求的原生响应中读取，并使用协议已有的目标 ID/连接类型/请求生命周期关联；超时或已取消请求的结果不能复用为新连接。中继主机与端口必须属于该部署明确配置的允许范围，回包不能扩充任意中继地址。
- 实际连接前检查候选地址及端口（1–65535）：拒绝未指定、回环、链路本地、组播和广播目标。`self_hosted` 中从信令获得的私网地址仅在上游标记为本地路径且命中显式家庭 CIDR 时允许，以保留同网段直连；显式局域网 IP/发现入口也受家庭 CIDR 约束。IPv6 未验收时保持关闭，后续须覆盖 ULA 与 IPv4 映射地址，不能借另一种表示绕过同类限制。
- 上述关联和地址过滤不等于给 endpoint 增加签名，也不意味着每条 hbbs 信令都已加密认证。对端 ID/公钥、会话加密与密码继续由上游握手验证；锁定版本的非安全回退必须专项检查，无法以既有配置/外围拒绝满足安全门禁时暂停公网发布，不能私自改签名协议。
- 纯内网模式继续禁止公网 STUN。公网模式不自动使用上游硬编码的第三方 STUN；若某路径需要该服务，先验证可配置性与自建替代，再明确其访问范围；不能验证时保持该路径关闭。
- 关闭旧版“纯内网”开关不自动获得公网权限。模式迁移和显式配置规则见 6.5；配置失败、服务器故障和重连都不得静默扩大访问范围。

## 4.5 公网能力基线与兼容性

本次设计以仓库锁定的客户端 RustDesk 1.4.9、OSS 服务端 1.1.16 为待验证组合，不因新增需求自动升级依赖或改用 Pro。

| 能力 | 设计处理 |
| --- | --- |
| TCP P2P 与自建中继 | 复用现有上游路径，先以官方同版本客户端做跨网验证，再验证 HomeDesk 定制包；同时检查缺失/错误 Key、对端签名异常及非安全回退行为 |
| UDP/KCP 会话数据路径与 IPv6 P2P | 当前自建配置未显式启用时默认关闭；分别证明服务端兼容、开关生效和实际会话使用该路径后才启用 |
| IPv6 网络策略 | 与 IPv6 P2P 一并验证地址分类、来源限制、监听和防火墙；不以存在 AAAA 记录证明支持，未验收的路径保持关闭 |
| 任意 NAT/移动网络 | 不保证打洞成功；应验证中继兜底与失败提示，并记录真实网络条件 |

[官方高级设置说明](https://rustdesk.com/docs/en/self-host/client-configuration/advanced-settings/#enable-udp-punch)列出的 UDP/IPv6 能力涉及客户端与 Server Pro 版本，不能据此推定锁定的 OSS 组合支持。P2P、TCP/UDP/IPv6、端到端加密须分别验收；hbbs UDP 心跳或打洞包不能作为会话 UDP 传输证据。

“UDP/KCP 未启用”仅指上述可选会话数据路径，不等于关闭客户端注册保活或服务端 UDP 21116。部署仍按 4.2 开放必需的 hbbs TCP/UDP，T-17 分别记录锁定版本的心跳、NAT 探测/打洞协调和会话数据用途，禁止以禁用全部 UDP 来实现该开关。

# 五、服务端设计

## 5.1 组成与部署

- **形态 A（纯内网默认）**：Docker Compose——`hbbs` + `hbbr` + `console` 部署于家庭主机，数据卷持久化密钥与 SQLite
- **形态 B**：systemd 裸机部署（服务端也可跑在信创/ARM 主机上，上游提供 amd64/arm64 二进制）
- **形态 C（自建公网）**：公网可达主机部署 `hbbs` + `hbbr`，Console 继续留在家庭 NAS；也允许家庭主机经可验证的公网地址和端口映射提供 hbbs/hbbr。不得假设家庭宽带一定有可入站的公网 IPv4，CGNAT 环境需另选可达主机或使用 VPN 方案。
- 密钥管理：hbbs 首启生成 Ed25519 密钥对；**公钥固化进客户端**，私钥只存服务端数据卷（另备份到 NAS 加密目录）
- 资源基线：内网三进程常驻内存目标 < 200MB；公网需另测连接数和中继带宽，不把低信令流量等同于中继低成本
- **内网部署目标**：飞牛NAS（fnOS，Debian 系，自带 Docker/Compose）跑形态 A；mini 主机作主力主控/被控端，兼任服务端备机。公网主机、域名和可达方式在 T-17 验证时确定，文档只保留占位值。
- 升级策略：镜像 tag 固定版本、手动升级（先备份数据卷），不追新

公网部署要求：

1. 分离“本机监听地址”和“向客户端通告的中继地址”；公网主机也可能只有私网网卡，不能继续要求两者相同。通告地址必须能从目标外部网络访问。
2. 增加独立的公网部署配置/校验路径，保留现有内网部署默认值；禁止通过放宽原内网校验让旧部署意外暴露。镜像版本、密钥卷和备份方式保持锁定与可恢复。
3. 按 4.2 验证服务器端口、防火墙及必要映射；域名存在时检查 DNS 与实际连接地址。HTTP 反向代理不能代替原生 TCP/UDP 服务的可达性。
4. 核验锁定版本的服务接入限制、日志以及可用的连接数/带宽保护，防止自建中继被滥用；服务器公钥是身份校验材料，不应被当作秘密令牌或家庭成员权限系统。
5. 同一设备群使用一致的自建连接服务器和公钥；首版不引入多服务器身份同步或自动切换公私服务器。公网服务不可达时按 4.3 使用局域网旁路。
6. `docs/DEPLOY.md` 的现有步骤仍仅适用于内网。T-19 通过后才补充公网可操作部署手册，本次设计修订不授权自动修改路由器、防火墙或真实服务。

## 5.2 Home Console（自研）

- 技术栈：**Rust（axum）+ SQLite + 服务端渲染模板（askama）+ 少量原生 JS**；单二进制，交叉编译 amd64 / arm64 / loong64
- 设计原则：**只读为主、不承载远控能力**（console 被攻破也拿不到远控权限）；仅两类写操作：WOL、设备备注/分组
- 在线状态数据来源决策：
    - ~~方案 A：直读 hbbs 的 SQLite~~（内部结构无兼容承诺，上游升级即碎）
    - ✅ 方案 B：**被控端主动上报**——fork 内新增轻量上报模块（HTTP POST，间隔 60s）；解耦上游内部结构，还能拿到 hostname/版本/架构等 hbbs 没有的信息
- API（v1，仅内网 + 静态 Token）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | /api/v1/heartbeat | 心跳：id、hostname、platform、arch、version、ip、mac |
| POST | /api/v1/session | 会话事件：start/end、对端 id、对端 ip |
| GET | /api/v1/devices | 设备列表（页面同源使用） |
| POST | /api/v1/wol | 对指定设备发魔术包 |
- 页面：设备墙（卡片：名称/房间/在线绿点/最近在线/WOL 按钮）、审计流水、设置（网段、Token、日志保留天数）
- **手机浏览器可用是硬要求**（家里最常用的入口是手机）

公网模式下的功能边界：

- Console 仅接受受控家庭网段或显式配置的 VPN 网段；VPN 接入方式须与现有绑定/来源校验兼容，不以放宽为全网段实现可达。
- 外出且未接入 VPN 时，客户端提供 ID/最近连接入口；设备墙显示“设备中心当前不可达”，不能把无心跳简单解释为设备不能远控，不能伪造公网在线状态。
- 家中被控端仍可上报跨网会话；在外设备无法访问 Console 时按既有有界队列和退避策略降级，队列溢出/退出/长期故障可能丢失事件，本阶段不承诺完整公网审计。
- 外出客户端默认关闭 Console 上报；只有明确配置的可信家庭/VPN 路径才启用。RFC1918 地址在不同网络可能重复，不能仅因目标是私网 IP 就向其发送共享 Token。
- WOL 由家中常开 Console 发出局域网广播，外网请求先经 VPN 到 Console；P2P 本身不能唤醒已关机且无在线代理的设备，也不向公网映射 UDP 9。
- 将来如需公网设备中心，另行设计 HTTPS、客户端独立凭据、撤销与权限隔离；不复用当前静态共享 Token 直接开放公网 API。
- VPN 为可选对接能力；尚未具备 VPN 时只验收 Console 不可达的降级边界，不要求完成 T-13 才能发布已验证的公网远控。

## 5.3 数据模型（SQLite）

| 表 | 字段 | 说明 |
| --- | --- | --- |
| device | id TEXT PK（RustDesk ID）、name、hostname、platform、arch、version、ip_last、mac、room、owner、online_at、created_at | 心跳 upsert |
| session_log | seq INTEGER PK、device_id FK、peer_id、peer_ip、action(start/end)、at、duration_s | 被控端上报 |

## 5.4 HomeDesk 统一门户（2026-10-01）

用户确认以 HomeDesk 桌面客户端首页为统一门户。新增“家庭服务”入口，对接 home-tunnel Server 10.1.0 的现有账号管理 API；家庭设备、RustDesk 远控、WOL 与内网 Console 继续按原设计工作。

本节当前完整范围由用户后续“完成方案并按目标模式完成所有开发，不中途询问”授权替代此前仅查看目录的首阶段范围。详细实施与验收矩阵见 [PORTAL_INTEGRATION_PLAN.md](PORTAL_INTEGRATION_PLAN.md)，发生冲突仍以本文件为准。

- 用户在本机输入自己的 HTTPS 服务端 origin、账号、密码及需要的 MFA 验证码，点击登录后读取账号所属设备和服务。使用未绑定设备的原生账号会话，不注册 FRP 设备、不申请隧道租约、不接入 home-tunnel 的原生远控。
- 门户完整查看、刷新、筛选账号所属设备与服务。HTTP/HTTPS 在系统浏览器打开，TCP/UDP 只显示和复制准确公网端点；在 HomeDesk 内创建服务、编辑名称/本地目标、暂停/恢复和删除。删除使用应用内确认，操作有互斥与进度反馈，不经聊天向用户确认。
- 编辑以接口返回的版本号提交，409 保留原草稿并要求在应用内刷新核对后明确重试；写操作超时或响应丢失显示结果未知，刷新读取状态，不自动重放。权限/端口池/协议能力以服务端返回为准，不能通过 UI 或构造请求越权；公网端口由服务端按现有自动分配规则提供。
- 设备标签、收藏使用版本保护的账号元数据接口；设备名称只读。10.1.0 仅允许设备自己的绑定会话改名，本门户不得为改名登记为 FRP 设备。连接的传输类型与已分配公网端口不可 PATCH 修改，切换传输需新建连接。账号改密/MFA配置、自定义域名/高级访问策略、管理员用户/端口池管理继续通过原管理台，浏览器不接收 Token。
- 公网 API 接入要求后台配置已确认且有效模式为 `self_hosted`；`lan_only`、配置保存进行中和确认未知时禁止登录、恢复、刷新、轮询、写操作及打开公网入口。登录不能隐式切换模式。首次主页不访问公网；只有用户进入“家庭服务”并明确登录，或该入口恢复此前明确勾选记住的账号，才访问该 origin。
- 使用独立适配模块，只允许该 HTTPS origin 下的明确认证、账号目录和账号所属资源操作路由，校验 TLS、不使用代理、不跟随重定向；不放宽现有普通 HTTP/下载白名单，不发送 Console 共享 Token，不调用 `/admin`、FRP 租约或自研远控路由。
- Windows 默认不勾选“记住登录”。勾选后，仅刷新 Token、origin、账号标识及有效期进入独立的 DPAPI CurrentUser 密文文件；密码、MFA、访问 Token 不持久化。恢复需匹配本机用户此前显式批准、独立保存的合法 HTTPS origin，密文中的地址不能自行授予联网许可。批准 origin 变更也递增门户许可代次。加密失败拒绝保存，不降级明文；其他平台未接入安全存储时只提供内存登录，并准确提示。
- 原生刷新严格单次并串行。持久凭据在任何刷新请求之前原子消费，新的刷新 Token 加密落盘成功后才交付恢复会话；崩溃、失响应、保存失败不能重放旧 Token。恢复必须核对存储 origin 与服务端 `/auth/me` 的账号身份，拒绝绑定设备或受限远控会话；MFA 仅用户人工再次提交。
- 正常导航和关闭应用终止内存/在途请求，保留已成功加密保存且未消费的刷新凭据；显式退出、网络许可代次变化、刷新失败/失响应、身份不符则条件销毁本实例拥有的记住记录和在途保存事务，不能让旧实例的迟到清理删掉另一实例在新许可下明确建立的新登录。仅明确“忘记登录”操作可全局清除。保存事务使用持久代次防止退出后迟到写入复活凭据。后台确认失效和有效配置变更递增网络许可代次，每个 API 实例固定该代次，快速恢复公网不能复用旧内存会话；尚未恢复的记录在纯内网中不读取、不消费、不联网，仍须匹配本机批准地址与新的有效许可后复验账号身份。
- 设备与服务按 home-tunnel UUID 关联，完整读取分页。其心跳/隧道状态明确标为服务连接状态，不推断 RustDesk 在线，不按 hostname/IP 自动合并远控设备；没有 UUID–RustDesk ID 绑定和集中远控授权。

该接入扩展的是已明确配置的公网管理端点，不开放原 HomeDesk Console；其内网/VPN 范围和 WOL 广播位置保持不变。服务端与 `hbbs/hbbr` 可同宿主机独立部署、独立数据卷和端口；不通过 HTTP 网关转发 RustDesk 核心连接、不共享 SQLite 内部表、不将 home-tunnel 账号撤销冒充远控设备授权撤销。

验证包含 HTTPS/origin/重定向边界、分页与所有声明的资源操作、403/409/写结果未知、MFA 与单次刷新、真实 Windows DPAPI 密文/原子消费/并发失效、自动恢复、在途撤权和迟响应隔离、导航保留会话、服务地址打开与端点复制、窄窗口与大字体。真实账号、公网服务和独立设备联调另记验收结果，不以合成测试替代。

### 5.4.1 运维验收环境与便携外壳边界（2026-10-02）

实机报告确认指定腾讯云尚未找到可核验的 home-tunnel 实例，本机干净 Windows 测试身份/机器尚未就绪。业务未执行时不能标完整验收通过。可先完成固定官方发行物、独立 Compose/卷/秘密与预检脚本，准备不等于部署；生产 Caddy、域名、防火墙和 Windows 身份配置仍按现有明确授权处理。

Windows 配置和 IPC 分别按品牌目录和全机品牌管道命名；同品牌的独立 Windows 用户不能自动保证后台隔离，`--config`、改 CWD 或重定向 AppData 不属于完整 profile 隔离。优先在干净测试机/VM/Sandbox 运行指定包；新品牌变体只能单独记录工程证据，不能冒充原包实机通过。

便携外壳的解包缓存使用已校验构建 namespace 和版本 timestamp，位于该 namespace 的专用 portable 子目录；删除前核验所属标记、绝对边界与无符号链接/reparse。不得删除旧 `LocalAppData/rustdesk` 或整个品牌目录，删除失败不继续覆盖半成品。辅助 broker 从构建品牌派生，外壳不做全机按名称终止；客户端清理只对本程序目录下的真实进程映像操作，持有句柄再核对路径以避免 PID 复用误伤。均属外围包装/进程管理，不调整远控协议或密码核心。

| C5 | 网络模式：纯内网 / 自建公网；统一地址策略与迁移校验 | 见 4.4、6.5；真实跨网待验收 | 中 |

## 6.4 UI 信息架构（Gemini 审计对象）

- 主控首页：我的设备（分组卡片，数据来自 console）｜最近连接｜ID / IP 手动连接框
- 会话工具条：画质档（流畅/平衡/高清）、实际直连/中继与加密标识、剪贴板、文件传输、Ctrl+Alt+Del、断开；详情提供实际 TCP/UDP/IPv6 信息或“未知”
- 被控端托盘：ID / 临时密码、服务器连接状态、当前「纯内网 / 自建公网」模式；模式与本次会话的直连/中继状态分别展示
- 设置：常规（语言/开机自启）｜安全（固定密码/来源限制）｜网络（服务器状态，模式与服务器配置在高级设置内）｜关于（版本/开源声明）

## 6.5 构建配置、旧配置迁移与实施范围

以下为配置契约；本轮的实现入口与使用方法见 [CLIENT_NETWORK.md](CLIENT_NETWORK.md)，实际验收范围以实现状态记录为准。

| 配置 | 约定 |
| --- | --- |
| `net.mode` | 新配置使用 `lan_only` / `self_hosted`，缺省为 `lan_only`；它是网络模式的唯一判定入口 |
| `server.host` / `server.key` | 保留为构建期所选模式的初始端点配置；按模式校验地址/域名，连接必须校验自建服务器公钥，不允许无 Key 降级 |
| `net.whitelist_cidr` | 保留家庭网段语义，供纯内网来源限制与局域网旁路使用；公网模式不把它自动当作所有远控来源的白名单 |
| 公网来源限制与打洞选项 | 在 T-18 确认既有上游配置映射后落地；公网来源限制是可选附加条件，设备认证始终必需；UDP/IPv6/STUN 受 T-17 兼容性结果约束 |
| `console.enabled/url/token` | 保持独立；切换公网模式不会自动修改 Console URL、放宽来源或开启上报 |

运行时按模式分别持久化原子配置组：`{mode, server.host, server.key, 家庭CIDR/来源限制, 打洞选项}`，`net.mode` 只选择当前生效组。已有构建字段初始化所选模式，旧内网配置迁入 `lan_only` 组；尚未配置的另一组保持缺省状态，不复制服务器或公钥凑出配置。切换时恢复该模式的完整有效组，或要求补齐并校验后再切换；例如仅配置公网 hbbs 的设备，不能凭空生成私网 hbbs 地址。保存/校验失败保留当前模式和原子组，UI 明确说明未切换。

迁移规则：

1. 未声明模式的旧配置保持纯内网；旧 `pure_lan_default=true` 映射到 `lan_only`。旧布尔值为 false 不能隐式映射为公网授权，必须补充明确的模式和合法服务器配置；新旧字段冲突应报错，不能猜测。
2. 旧设置中的“纯内网开关关闭”同样不授予公网权限。新增模式选择取代含义不清的总开关；高级设置保存前一次性校验服务器、公钥、来源与模式，校验失败保留上一份有效配置并提示原因。
3. 模式变更通过明确的“保存并重启服务”动作生效，界面提前说明将断开会话。重启后不复用旧公网连接/重试队列绕过纯内网限制；纯内网与公网配置可分别保存，不能把公网地址静默重写成旧内网地址。
4. 从纯内网升级到公网必须由本机配置操作显式选择，或使用明确按公网模式构建的产物；升级安装、导入不完整配置、网络切换和服务器故障均不能自动开启公网。高级设置入口是防误操作设计，不替代设备端认证或本机权限控制。
5. 保存请求有明确期限，忙队列立即拒绝；执行权与放弃请求互斥，过期或已放弃的排队请求不能迟到落盘。IPC 已发出但 ACK 未确认时，不能声称旧配置必然未变：只读同步后台有效组；无法同步则暂停 UI 进程的新连接和 Console 请求，提示用户恢复同步后核对模式。

最小改动范围：构建配置解析与验证、独立网络策略模块、现有连接入口的模式判断、配置导入/持久化、中文设置与状态、服务端部署校验及测试。已知需核对 `client/homedesk_build.rs`、`homedesk_config.rs`、`homedesk_net.rs`、`client.rs` 的地址检查和 `common.rs` 的打洞/STUN 开关，以及 `server/verify.sh`；构建脚本与 UI 的同类校验也必须一致。

不调整上游连接竞争顺序、NAT 穿透算法、传输协议、编解码或加密实现，不修改 hbbs/hbbr 源码。依赖升级若有必要，另开 PR 并重新完成兼容性验证。

# 七、信创适配方案

## 7.1 总策略

1. **x86_64 信创（海光/兆芯）≈ 普通 Linux**：优先直接用 x64 产物，问题多半出在 glibc 版本与桌面环境，不在 CPU
2. **aarch64（飞腾/鲲鹏）是信创主战场**：先实测上游 aarch64 构建；失败则在目标机源码编译（Rust 工具链对 aarch64 成熟）
3. **loongarch64 单列探索档**：生态限制集中在 UI 层（Flutter），所以砍 UI 保内核——纯被控 no-GUI 形态
4. **所有信创包必须离线可装**：deb/rpm 附依赖清单与安装脚本，不假设机器有可用软件源

## 7.2 已知坑与对策

| # | 坑 | 现象 | 对策 |
| --- | --- | --- | --- |

# 八、安全设计

| 层 | 机制 | 说明 |
| --- | --- | --- |
| 传输 | 端到端加密（沿用上游） | 直连与中继均必须验证加密，不允许为连通性降级为未加密会话 |
| 身份 | 服务器公钥固化并校验 | 拒绝错误 Key/未配置 Key；公钥本身不授予远控权限，也不是秘密 |
| 认证 | 被控端验证每设备独立固定密码或本地确认；临时密码可关 | 无人值守密码 ≥ 12 位随机，保留上游失败退避；不因换模式绕过认证 |
| 网络 | 纯内网保留家庭 CIDR 与零公网映射；公网采用显式连接服务和对端访问规则 | 按 4.4 执行；公网模式不再承诺“从公网无法触达” |
| console | 仅内网/受控 VPN + Token，不承载远控认证 | 不随公网模式开放 8080 或把共享 Token 发往不可信网络 |
| 审计 | 成功接收的会话流水保留 90 天 | 外网设备无法上报时存在缺失；实际连接类型不得凭配置推断 |
| 密钥 | 私钥只存服务端数据卷；仓库禁提交任何密钥（CI 扫描） | 见 11.2 铁律 5 |

威胁模型速查：

| 威胁 | 防线 |
| --- | --- |
| WiFi 密码泄漏、蹭网设备扫描 | CIDR 只限制来源范围；同网段设备仍必须通过设备密码/本地确认与防爆破 |
| 客户端安装包外流 | 公钥不构成秘密，无密码依然连不上 |
| 服务端主机被入侵 | 端到端加密降低中继读取内容的风险；仍可能泄露连接元数据、干扰信令或拒绝服务，需恢复可信服务并评估密钥轮换 |
| 家庭成员误操作 | 简化 UI + 高级项锁定 |
| 公网密码猜测或中继滥用 | 设备独立强密码/确认、上游失败退避、服务端接入与流量保护；不把分发公钥当作成员授权 |
| 旧设置/升级意外开放公网 | 缺省纯内网、显式模式迁移、无公共服务器回退，正反用例与抓包共同验证 |

# 九、性能指标与验收标准

| # | 指标 | 目标 | 及格线 | 测法 |
| --- | --- | --- | --- | --- |
| M1 | 内网直连率（同网段互通、无 AP 隔离的验收环境） | 100% | 100% | 会话信息显示「直连」；不外推到公网 |
| M2 | 端到端延迟（1080p60 有线直连） | ≤ 60ms | ≤ 100ms | 拍摄秒表对比 / 内置统计 |
| M3 | 帧率 | 1080p60（有线）/ 1080p30（WiFi） | 30fps | 会话统计 |
| M4 | 被控端 CPU（软编 1080p60） | ≤ 25%（x64 i5 级） | ≤ 40%（飞腾 D2000） | 采样 60s 均值 |
| M5 | 断线重连 | ≤ 3s | ≤ 10s | 拔网线 / 切 WiFi |
| M6 | 文件传输（千兆有线，单大文件） | ≥ 60MB/s | ≥ 40MB/s | 1GB 文件 + SHA256 校验一致 |
| M7 | 冷启动到可被连 | ≤ 30s | ≤ 60s | 重启计时 |
| M8 | 服务端常驻内存（3 进程合计） | ≤ 200MB | ≤ 400MB | docker stats |
| M9 | WOL 成功率（有线被控机） | ≥ 95% | ≥ 90% | 20 次采样 |
| M10 | 新机接入耗时（家人可独立完成） | ≤ 5min | ≤ 10min | 实测计时 |

M1–M10 保留既有家庭网络验收条件，不能将内网延迟、吞吐和直连率作为公网承诺。公网按下列矩阵另记结果；服务端资源需分别统计 hbbs 信令与 hbbr 中继。

## 9.1 公网模式验收矩阵

以下均为待执行项，结果记入 [tests/smoke.md](../tests/smoke.md)。先测官方锁定版本组合，再测同配置 HomeDesk 安装包；官方客户端通过不能代替定制版验收。

| 场景 | 必须验证的结果 |
| --- | --- |
| 纯内网回归 | 全新安装/旧配置迁移仍为 `lan_only`；运行 10 分钟且连接服务不可达时无应用发起的公网出站或外部服务 DNS 请求；M1–M7 不回退 |
| 两个独立外网（不同家庭宽带） | 连续建立 3 次会话，记录直连/中继、加密、建连耗时和实际传输；至少一个真实跨网环境完成加密 P2P，不能只用同路由器双机冒充公网验证 |
| 移动热点/存在 NAT 限制的网络 | 连续 3 次记录实际结果；可直连则直连，不能直连但双方可达中继时应完成加密中继；若服务也被阻断应准确报错，不承诺任意网络连通 |
| 中继与失败路径 | 在可恢复测试环境阻断直连，证明自动使用自建 hbbr；恢复后验证正常策略。停止 hbbr 时仍能在已证明可直连的环境新建连接；两条路径都不可用时有明确失败提示且不访问公共服务器 |
| 身份与来源策略 | 错误/缺失服务器 Key、错误设备密码、对端签名/ID 不符、显式来源限制外的连接均被拒绝；知道服务器公钥不等于获得设备访问权；直连与中继均验证认证和加密，不能落到非安全会话 |
| 模式切换与地址边界 | 旧布尔值不隐式开启公网；非法/冲突配置不替换有效配置；两模式原子配置组互不串用，目标组不完整时拒绝切换。公网切回纯内网并重启后无旧公网连接或重试残留；检查导入、DNS、返回地址、代理及 HTTP 重定向/下载边界 |
| 对端/中继候选地址 | 当前请求关联的公网对端可继续上游握手；非法端口、回环、链路本地、未指定、组播/广播、未获准私网与中继目标在连接前拒绝；自建公网模式的本地路径标记 + 家庭 CIDR 例外允许同网段直连。过期/取消请求不复用，地址过滤不能代替握手认证 |
| 服务故障与断公网 | 关闭公网 hbbs 或切断外网后，公网模式提示 ID 服务不可达并拒绝未加密 IP 绕过；原纯内网 IP/发现兼容行为另记，不能算加密会话验收通过；有效私网 ID 服务恢复后可重新连接 |
| 功能与管理台降级 | 跨网双向键鼠、中文剪贴板、文件 SHA256、锁屏/服务重启可用；Console/VPN 不可达不阻塞 ID 远控，设备墙说明不可达；未配置可信路径时不发 Console Token，WOL 只在家中广播 |
| UDP / IPv6（按能力分别记录） | 用版本、实际连接/抓包与会话证据证明支持；未验证或不支持时标“未启用/不支持”，保持关闭，不用服务端 UDP 心跳代替桌面流量证据 |

每个跨网成功场景至少保持会话 10 分钟，记录分辨率、编码、平均/峰值延迟、帧率、文件吞吐、中继字节量及测试网络限制；首轮用实测建立公网性能基线，不预设未经验证的延迟或打洞率。非相关系统进程的公网请求与 HomeDesk 请求分开归因。

发布门禁：已声明支持的平台与所选部署拓扑必须完成对应构建和矩阵；首批可先验收 Windows 双机与一种部署拓扑，未验收的 Linux/ARM64 或另一拓扑不宣称公网可用。可选 UDP/IPv6/VPN 未启用时标明未覆盖，不阻塞已验证的 TCP P2P + 中继发布；至少一组真实跨网 P2P 和失败中继路径必须通过。所有报告脱敏，真实地址、Key、Token 与原始敏感抓包只存未跟踪本地目录。

# 十一、工程规范与 Codex 协作

## 11.1 仓库结构（monorepo）

```
homedesk/
├── AGENTS.md            # Codex 工程铁律（11.2 落地为此文件）
├── docs/
│   ├── DESIGN.md        # 本方案（唯一契约，改动走 PR）
│   ├── DEPLOY.md        # 部署笔记（P0 产出）
│   └── XINCHUANG.md     # 信创编译笔记（P2 产出）
├── client/              # fork 自 rustdesk/rustdesk，保留上游 git 历史
├── server/
│   ├── compose.yml      # hbbs + hbbr + console
│   └── console/         # 自研：Rust axum + SQLite + askama
├── build/
│   ├── config.toml      # 品牌/服务器地址/Key/网络模式/网段，构建期注入
│   └── ci/              # win-x64 / linux-x64 / linux-arm64（loong64 用目标机脚本）
└── tests/
    ├── smoke.md         # 每 PR 手工冒烟清单（连接/文件/剪贴板/重连）
    └── console/         # console API 单测 + 集成测试
```

## 11.2 AGENTS.md 铁律（Codex 必守）

1. **最小侵入**：对 client/ 上游代码的每处修改加 `// HOMEDESK:` 标记；新功能优先独立文件/模块；禁止重排、重格式化上游代码——保住 rebase 上游安全补丁的能力
2. **不碰核心**：传输协议、编解码、加密逻辑零改动，只做配置、UI、外围模块
3. **配置外置**：品牌/服务器/Key/网络模式/网段一律走 build/config.toml 构建期注入，禁止散落硬编码
4. **每 PR 三件套**：三平台编译通过 + tests/smoke.md 勾选记录 + 变更说明（动了上游哪些文件、为何）
5. **零密钥入库**：CI 跑 secret 扫描；.gitignore 覆盖密钥与数据卷
6. **console 质量线**：API 全部有单测；单二进制、无额外运行时依赖
7. **依赖锁定**：Cargo.lock 与镜像 tag 固定版本；升级单独开 PR
8. **模式边界**：默认纯内网，只有显式配置的自建公网模式允许必要公网连接；两种模式均禁止公共服务器回退、遥测与自动更新，Console 范围不随模式扩大

## 11.3 任务卡模板（给 Codex 派活的格式）

```
T-xx 标题
```

以上保留原内网阶段任务关系；新增模式与旧开关迁移由 T-17～T-19 承接，见 [ROADMAP.md](ROADMAP.md)。本次仅文档变更，检查差异、链接和契约一致性，不填报未执行的编译或实机验收。
