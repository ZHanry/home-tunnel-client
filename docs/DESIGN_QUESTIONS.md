# 实现中待确认/后续完善项

## 2026-09-22 双模式设计决策

以下事项已由新设计替代旧的“公网只能通过 WireGuard 回家”口径，不再作为待确认项：

- 默认模式为 `lan_only`，保持零公网出站；只有构建默认或本机受控高级设置显式选择并通过整组配置校验的 `self_hosted`，才允许连接自建公网 hbbs/hbbr、必要 DNS、经审核的打洞服务及当前连接所需的对端公网地址。校验失败保留上一份有效配置，不静默改模式或扩大权限。两种模式都禁止上游公共服务器回退、遥测和自动更新。
- 公网连接沿用上游直连选择并以 hbbr 中继兜底；首版不新增“强制仅直连”产品开关，也不承诺公网直连率。P2P 不等同于 UDP。
- hbbs/hbbr 只负责注册、信令、打洞协调和中继；远控密码仍由被控端校验，服务端 Key 不是用户权限，不引入中央远控授权。
- 公网 hbbs/hbbr 可部署在公网主机或公网可达的家庭主机；Console 仍只允许内网或 VPN 访问。没有 VPN 时，设备墙、上报、WOL 可能不可用，ID 和最近连接仍可用；不承诺完整审计。
- `net.mode` 是模式的唯一入口；旧 `pure_lan_default=true` 映射为 `lan_only`，旧 `pure_lan_default=false` 也不能隐式启用公网。模式必须显式保存，重启客户端服务后生效，并终止旧会话与上报队列。
- 外出客户端默认关闭 Console 上报；只有明确可信的家庭网络或 VPN 路径才可启用，不能仅凭酒店等网络也可能使用 RFC1918 地址就发送共享 Token。
- 家庭 CIDR 入站限制只适用于 `lan_only`。`self_hosted` 必须按模式定义公网来源策略，并始终保留设备密码等设备认证。
- 实施核查替代原“公网故障 IP/发现保底”：锁定上游的 IP/域名直接连接绕过安全握手，`self_hosted` 应拒绝并提示 ID 连接；经 hbbs 撮合的同 LAN P2P 保留。`lan_only` 原兼容入口不等于加密验收通过，详见 [T17_VALIDATION.md](T17_VALIDATION.md)。

仍需 T-17～T-19 实测后关闭的问题：

- 固定 `rustdesk-server` OSS `1.1.16` 与锁定官方客户端及 HomeDesk 定制包，必须完成真实跨网 TCP P2P 和自动中继；不同 NAT/运营商分别记录，UDP/IPv6 未验证时保持关闭并标明未覆盖。
- 分开辨认 hbbs UDP 21116 的注册/心跳/打洞协调与可选 UDP/KCP 会话流量，不能为了关闭未验证的会话 UDP 而破坏注册保活，也不能用心跳包冒充会话证据。
- 锁定版本对错误/缺失服务器 Key、对端签名或 ID 不符及已知非安全回退的实际处理；不能假定 hbbs 的所有 endpoint 回包都已签名。若无法仅靠现有握手、配置和外围拒绝达到门禁，应暂停公网发布，不自行新增签名协议。
- 对端/中继候选是否严格关联当前配置服务器、当前请求目标 ID/连接类型/生命周期，并拒绝过期取消结果、非法端口与未指定/回环/链路本地/组播/广播地址；同 LAN 私网例外必须同时满足上游本地标记和显式家庭 CIDR。
- 必要 DNS 与打洞服务的精确允许列表，以及是否存在未识别的公网依赖；必须以源码清单和抓包为证。
- 公网来源策略如何替代家庭 CIDR，同时避免把设备认证误当作网络白名单的替代品。
- 模式切换保存、服务重启、旧会话终止和上报队列清理能否避免跨模式复用连接或凭据。
- 外出客户端的 Console 上报默认关闭，以及仅在可信家庭/VPN 路径启用的判定与抓包证据。
- 公网 hbbs/hbbr 故障、DNS 故障和断公网时，既有会话、ID 新建连接、IP 直连与局域网发现的实际边界。
- Console 在无 VPN 的公网场景中，设备墙、心跳、审计和 WOL 的具体降级表现与用户提示。
