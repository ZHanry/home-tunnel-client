# HomeDesk 家庭服务门户

本页对应 [DESIGN.md 5.4](DESIGN.md#54-homedesk-统一门户2026-10-01)。统一入口在 HomeDesk 桌面首页，home-tunnel 提供服务目录和隧道基础设施，RustDesk 继续提供远程桌面。

## 使用

1. 在 HomeDesk 本机网络设置中显式选择并保存完整有效的 `self_hosted` 配置。纯内网模式、保存进行中或后台确认未知时不允许公网服务门户请求，登录不会自动改变模式。
2. 打开左侧“家庭服务”，输入自己的 home-tunnel HTTPS 地址、账号和密码。地址只填 origin，例如 `https://console.example.com`，不填 `/api/v1`、路径、查询参数或账号信息。
3. 若账号启用双重验证，再手动输入动态码或恢复码并提交。应用不会自动重试验证码。
4. 登录后查看账号全部设备与服务，可按设备筛选。HTTP/HTTPS 使用“打开服务”在浏览器访问；TCP/UDP 使用“复制访问地址”，交给对应应用连接。
5. 在设备卡点击“添加服务”创建 HTTP/HTTPS、TCP 或 UDP 服务；现有服务可编辑、暂停/恢复或删除。TCP/UDP 仅在服务器已授权账号及端口池后可创建，公网端口由服务端分配。
6. 在“管理设备”编辑标签或收藏。10.1.0 的账号接口不允许给另一设备改名，名称需要在设备自己的 home-tunnel 客户端修改。
7. 保存提示版本冲突或结果未知时，保留草稿，点击“刷新核对”查看服务器当前配置，再在应用内明确确认核对后重试。创建/编辑不会因网络超时自动重放，删除需要应用内确认。
8. 接入新设备、账号密码/MFA、自定义域名/高级访问策略和管理员设置仍可点击“打开管理台”。浏览器单独登录，不从 HomeDesk URL 接收 Token。

Windows 用户可在登录时勾选“记住登录”，下次进入家庭服务页会恢复该账号；默认不勾选，其他平台暂只提供内存登录。已登录后也可点击“忘记登录”删除保存的密文并继续当前内存会话。

密码、验证码和访问 Token 不写入文件。记住登录仅用 Windows 当前用户 DPAPI 加密 origin、账号标识、刷新 Token 和有效期；加密或恢复失败不会降级明文。

退出登录只结束本门户的账号会话，并条件销毁其拥有的刷新凭据，不撤销设备凭据、Agent 或既有 FRP 隧道。正常关闭应用保留已成功保存的记录；切换网络许可会终止旧会话并使其保存事务失效，迟到写入不能复活。其他实例在新许可下明确建立的新登录不被旧实例的清理误删。

页面已登录后每 30 秒刷新，可手动刷新；导航之间切换保留会话。首次主页和纯内网状态不读取恢复凭据或联网，记住记录只有匹配本机明确批准的 HTTPS 地址并通过新的动态许可才能恢复。

## 范围与身份

服务设备使用 home-tunnel UUID，服务通过 `device_id` 关联对应设备。其在线状态表示隧道设备心跳，服务状态表示转发连接状态；不能据此推断 RustDesk 是否可远控。首阶段不按设备名或 IP 自动合并，也不提供 UUID–RustDesk ID 绑定。

家庭设备、设备 ID 远控、WOL 和内网 Console 仍使用原入口。门户不安装 Agent、不注册隧道设备、不启动转发引擎，也不连接 home-tunnel 自研远控协议。

## API 与网络边界

目标契约为 home-tunnel Server 10.1.0 的 `api-v1.5.0`。核查源码为 [866e0cbb](https://github.com/ZHanry/home-tunnel-server/tree/866e0cbb9ac89de39491ca353574f517f374554e)，接口说明见其 [API 文档](https://github.com/ZHanry/home-tunnel-server/blob/866e0cbb9ac89de39491ca353574f517f374554e/docs/API.md)。

- 登录调用 `/api/v1/auth/login`，使用真实平台的原生账号会话。登录后 `/auth/me` 必须确认 `device_id=null`，拒绝设备或受限原生远控会话。
- 目录使用 `/client/devices` 与 `/client/connections`，完整读取分页；超过契约限额、重复数据或分页期间目录变化时明确报错，保留旧目录供再次刷新，不宣称截断结果完整。写操作仅调用该账号所属的连接 CRUD、设备元数据和子域可用性接口，不调用 `/admin`。
- 身份维护使用 `/auth/refresh` 和 `/auth/session/close`。刷新为单次串行，持久 Token 在请求前原子消费，新 Token 成功加密保存后才交付恢复登录；失响应不能重放旧 Token。失败或身份不符清空本实例会话及所属事务。
- 所有 API 只向用户输入的同一个 HTTPS origin 发送，使用系统 TLS 验证、DIRECT 且不跟随重定向。响应有总时间和大小上限，服务端错误不会原样回显凭据或任意文字。
- Rust 动态许可同时检查已确认的公网模式及配置保存状态；每次保存、确认失效和有效配置变更更新许可代次。API 实例固定该代次，许可撤销后关闭在途请求，即使很快恢复公网也不接收旧响应或复用旧凭据。

home-tunnel 当前没有只读 Token scope。门户只调用设计明确的账号路由和操作，遵守资源版本、协议能力与账号权限；Windows 持久凭据独立存于应用支持目录下的门户子目录，包含密文、非秘密事务代次和锁文件，不写入普通账号配置或仓库。

本功能不放宽原 HomeDesk 普通 HTTP/下载范围，不向公网发送内网 Console 共享 Token，也不开放 Console 端口。

## 验证与未覆盖项

本地行为测试使用合成账号、目录和回环 mock；组件测试通过注入接口与浏览器/剪贴板回调，不使用真实凭据。具体本轮执行结果见 [实现状态](IMPLEMENTATION_STATUS.md) 和 [smoke.md](../tests/smoke.md)。

本轮增加真实回环 HTTPS 探针（不可信证书/错误主机名拒绝、正确信任链成功）与真实 Windows DPAPI 临时目录测试。尚未使用你的真实 home-tunnel 账号进行公网 HTTPS/MFA、撤权、设备管理和实际服务访问联调；Linux/ARM64 完整客户端构建与实机未由本轮 Windows 验证替代。RustDesk 跨网 P2P/中继仍遵循原专项验收，门户完成不等于远控网络验收完成。

完整设计与交付范围见 [PORTAL_INTEGRATION_PLAN.md](PORTAL_INTEGRATION_PLAN.md)。
