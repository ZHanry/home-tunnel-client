# HomeDesk 自建公网 hbbs/hbbr 部署

本文只部署公网可达的 RustDesk OSS `hbbs` 与 `hbbr`。Home Console、WOL 和家庭设备的 IP 直连监听继续留在家庭内网或受控 VPN，不随公网模式开放。

当前状态是**开发支持已完成，真实公网验收待执行**：仓库已经完成配置拒绝测试、Compose 展开校验和本机回环容器测试；尚未证明任何真实域名、云防火墙、家庭路由器、运营商 NAT、跨网 P2P、中继兜底或十分钟会话指标。完成 `docs/DESIGN.md` 9.1 的真实网络矩阵前，不应把公网安装包标记为已发布。

## 1. 支持的拓扑

### 独立公网主机

```text
外部客户端 ── Internet ── 公网 IPv4/DNS ── 公网主机 hbbs/hbbr
家庭客户端 ── 家庭 NAT ────────────────┘
家庭 NAS ── Home Console（仅内网/VPN）
```

公网主机可能只有云厂商分配的私网网卡，公网地址由云边界做 DNAT。此时：

- `HOMEDESK_PUBLIC_BIND_IP` 填主机实际拥有的私网接口 IPv4；
- `HOMEDESK_PUBLIC_RELAY_HOST` 填外部客户端能访问的公网域名或公网 IPv4；
- 云安全组、主机防火墙和 DNAT 由管理员逐层核对，仓库脚本不会修改它们；
- 家庭路由器不需要给每台被控机配置固定端口映射。

### 家庭主机提供公网服务

```text
外部客户端 ── Internet ── 家庭公网 IPv4 ── 路由器端口映射 ── 家庭主机 hbbs/hbbr
家庭客户端 ────────────────────────────────────────┘
```

这一路径要求家庭宽带确有可入站的公网 IPv4。CGNAT 地址不能用普通端口映射变成公网服务；应改用独立公网主机或受控 VPN。还需验证 NAT 回环，或为家庭内外客户端提供解析结果一致且实际可达的 DNS 方案。不要启用路由器 DMZ，也不要用 HTTP 反向代理代替原生 TCP/UDP 转发。

## 2. 固定版本与暴露面

公网编排仍固定为：

```text
ghcr.io/rustdesk/rustdesk-server:1.1.16
sha256:8ecdab65deb7c84652a626380e31d11a8f1fbafd97916d57f95c20628f943c00
```

只允许以下宿主机端口：

| 协议 | 端口 | 进程 | 用途 |
| --- | ---: | --- | --- |
| TCP | 21115 | hbbs | NAT 类型测试 |
| TCP + UDP | 21116 | hbbs | 注册、心跳、信令与打洞协调 |
| TCP | 21117 | hbbr | 加密中继数据 |

禁止顺带发布 TCP 21118/21119 WebSocket、Console TCP 8080、WOL UDP 9 或任一被控端 IP 直连端口。镜像内的进程可能在容器网络中监听 WebSocket 端口，但 `compose.public.yml` 没有把它们发布到宿主机；防火墙放行清单也不得包含它们。

## 3. 部署前准备

1. 安装 Docker Engine 与 Compose v2，确认 `docker compose version` 可用。
2. 为公网主机确定一个实际接口 IPv4。禁止使用 `0.0.0.0`、回环、链路本地、组播、保留、文档测试地址或 IPv6。
3. 确定外部客户端可访问的公网域名或公网 IPv4。域名只填主机名，不带 `http://`、路径、通配符或端口。
4. 域名场景先检查 A 记录；存在 AAAA 记录不代表本项目已支持 IPv6，未完成 IPv6 验收时应删除或停止发布错误的 AAAA 路径。
5. 核对云安全组、主机防火墙或家庭路由器映射的目标地址。只准备第 2 节的四条协议/端口规则，不在此时修改 Console 或 NAS 管理端口。
6. 确保部署目录与 `server/public-data` 所在磁盘持久化、空间充足，并准备一个受控的加密备份目录。

可在主机本地执行以下只读检查；占位符必须替换为自己的域名，结果不要贴入公开工单：

```bash
getent ahostsv4 '<公网域名>'
ip -4 address show
ss -lntup
```

DNS 返回地址必须与实际公网入口一致。外部可达性要从另一条真实网络检查，本机 `localhost` 或同一路由器下的连接不能代替公网测试。

## 4. 填写并校验配置

进入仓库的 `server` 目录：

```bash
cp .env.public.example .env.public
chmod 600 .env.public
```

编辑三个值：

```dotenv
HOMEDESK_PUBLIC_BIND_IP=<主机实际接口IPv4>
HOMEDESK_PUBLIC_RELAY_HOST=<公网域名或公网IPv4>
HOMEDESK_PUBLIC_RELAY_PORT=21117
```

`.env.public` 是未跟踪的本地配置。真实 IP 或域名只保存在这里，不要写回 example、文档、提交记录或公开日志。校验脚本逐行读取固定键，不使用 `source` 或 `eval`，并以已校验值覆盖同名父进程环境变量。

先只校验，不拉取或启动容器：

```bash
bash ./verify-public.sh --config-only
```

校验范围包括监听地址是否属于当前主机 IPv4 接口、地址和端口、域名 A 记录是否全部为普通公网 IPv4、服务集合、固定镜像 digest、展开后的端口白名单、监听/通告地址分离，以及 hbbs/hbbr 的密钥校验参数。域名尚未生效、只解析到 IPv6、混入私网/保留地址，或系统缺少 `ip`/`getent` 时都会拒绝部署。查看实际部署入口：

```bash
bash ./verify-public.sh --print-command
```

输出会要求再次调用校验脚本，避免用户稍后直接执行 Compose 时被父进程中的同名环境变量覆盖。确认无误后启动：

```bash
bash ./verify-public.sh
```

脚本只执行镜像拉取、Compose 启动和容器状态检查；不会修改云安全组、主机防火墙、路由器、DNS 或任何未指定公网服务。

## 5. 防火墙和外部可达性

在云安全组或主机防火墙中手工创建四条入站规则：TCP 21115、TCP 21116、UDP 21116、TCP 21117。公网模式不再自动套用家庭 CIDR；如果家庭成员的出口地址稳定，可以额外缩小来源范围，但移动网络和家庭动态公网地址可能因此无法接入。

在一台真正位于外部网络的主机上验证 TCP：

```bash
nc -vz '<公网域名>' 21115
nc -vz '<公网域名>' 21116
nc -vz '<公网域名>' 21117
```

普通 `nc` TCP 成功不能证明 UDP 21116、RustDesk 注册、P2P、加密或中继成功。UDP 必须结合服务端日志、抓包和真实客户端行为判断；测试材料要脱敏并存放在未跟踪目录。验证后再次检查宿主机监听与容器端口，确认没有 21118、21119、8080 或 UDP 9。

## 6. 服务器密钥与设备权限

首次启动会在 `server/public-data` 生成：

- `id_ed25519`：服务器私钥，只能留在服务端数据卷和受控加密备份；
- `id_ed25519.pub`：服务器公钥，可以分发给客户端，用于核验自建服务器身份。

公钥不是密码、Token 或家庭成员名单。知道公钥不会自动获得设备控制权；被控端仍必须验证独立强密码或本地确认。公网编排为 hbbs 与 hbbr 都传入 `-k _`，要求客户端使用服务器密钥校验路径，不能把它解释成账户系统或细粒度授权。

锁定的 OSS 1.1.16 `--help` 只提供 `-k/--key` 这类共享密钥校验，没有账户、家庭成员、设备 ACL 或按用户配额。项目不把私钥文本写入 `.env.public`，也不通过命令行分发私钥。需要成员级集中授权时，当前 OSS 基线不满足该需求。

## 7. 日志、流量保护与观察

`compose.public.yml` 使用 Docker `local` 日志驱动，并把单文件轮转限制为 10 MiB、最多 5 个文件。日志仍可能包含客户端地址、设备 ID 或连接元数据，只在部署主机本地按需查看，不要原样上传：

```bash
docker compose --env-file .env.public -f compose.public.yml logs --tail 100 hbbs hbbr
```

本机对锁定镜像的实际检查结果：

- `hbbs --help` 提供配置、密钥、监听端口、中继地址、UDP 接收缓冲等选项；
- `hbbr --help` 只列密钥和监听端口，没有连接数或按成员配额选项；
- hbbr 1.1.16 启动日志显示 `TOTAL_BANDWIDTH=1024 Mb/s`、`SINGLE_BANDWIDTH=128 Mb/s`、`LIMIT_SPEED=32 Mb/s`、降级阈值 `0.66`、检查延迟 `1800s`；这些是锁定二进制的默认中继保护，不是本项目对公网带宽或抗攻击能力的承诺；
- OSS 支持 `blocklist.txt` 拒绝来源 IP、`blacklist.txt` 对来源 IP 限速，但 NAT 出口可能代表多个合法客户端，名单变更必须在可恢复窗口测试，不能代替设备认证；
- 没有发现原生最大连接数、成员级限额或完整 DDoS 防护。云厂商流量告警、账单告警、主机防火墙的连接速率控制和上游清洗需要按实际平台另行配置。

查看容器状态和一次性资源/网络累计量：

```bash
bash ./public-ops.sh status
bash ./public-ops.sh stats
```

`docker stats` 的网络累计量是容器总量，不能区分信令、P2P 和某个中继会话。真正的中继字节量与连接类型仍要按 9.1 的客户端会话证据和服务端日志记录。

`status`、`stats` 和 `backup` 只核对本地配置结构与 Compose 安全边界，不要求 DNS 或原监听接口当下可用，因此可在网络故障时排查和备份。这个运维校验不能启动服务；`verify-public.sh` 的启动与部署检查始终重新执行接口和公网 DNS 校验。

## 8. 备份、恢复与回退

创建一致性备份：

```bash
bash ./public-ops.sh backup '<已存在的加密备份目录>'
```

脚本要求 hbbs/hbbr 同为运行或同为停止；运行时会短暂停服，归档 `public-data` 后恢复原运行状态。归档权限为仅当前用户可读，并包含服务器私钥，不能放到公开同步目录。
备份目标不能等于或位于 `server/public-data` 内部。创建归档失败时，脚本删除本次半成品并尝试恢复原运行状态，不会输出“备份完成”。

恢复会覆盖当前身份和运行数据库，因此没有自动脚本。维护窗口内手工执行时：

1. 停止公网 Compose，保留当前 `public-data` 为带时间戳的旁路副本；
2. 在空目录解压备份，核对所有权和权限，再原子替换数据目录；
3. 运行 `bash ./verify-public.sh --config-only`，再启动服务；
4. 只比较恢复前后公钥是否一致，不输出私钥内容；
5. 从真实外网重做注册、加密直连或中继、失败提示和十分钟稳定性测试。

需要紧急回退公网服务时，在部署主机执行：

```bash
docker compose --env-file .env.public -f compose.public.yml stop hbbs hbbr
```

随后由管理员撤销四条公网入站规则或端口映射，并把客户端原子切换到一份已经验证有效的 `lan_only` 私网 ID 服务器配置后再连接。不要删除 `public-data`；保留它用于恢复身份和审计。`self_hosted` 下公网 hbbs 故障时不承诺新建连接，也不降级到手输 IP/域名的原始 TCP 路径：锁定上游的该入口不执行安全握手，HomeDesk 会拒绝并提示使用设备 ID。原 `lan_only` 的 IP/发现兼容行为单独记录，不能作为加密通过的证据。

## 9. 真实公网验收清单

部署完成后仍必须执行并记录：

1. 官方锁定版本客户端与 HomeDesk 定制客户端分别使用正确 Key 注册；缺失/错误 Key 均失败。
2. 两个独立外网连续建立三次会话，区分直连与中继，并验证认证和加密。
3. 在可恢复测试环境阻断直连，确认自动使用自建 hbbr；再停止 hbbr，验证可直连路径与完整失败路径。
4. 移动热点或受限 NAT 下记录真实结果，不承诺任意网络都能打洞。
5. 每个成功场景保持十分钟，记录建连时间、延迟、帧率、文件 SHA256/吞吐、服务端资源与中继字节量。
6. 断开公网服务后确认 `self_hosted` 新建连接明确失败、手输 IP/域名的原始 TCP 路径被拒绝，并且没有公共 RustDesk 服务器回退；再原子切换到有效 `lan_only` 私网 ID 服务器组，验证经私网 hbbs 撮合的同 LAN P2P。原 `lan_only` IP/发现兼容行为另记，不能当作安全握手或加密证据。
7. 确认 Console 8080、WOL UDP 9、WebSocket 21118/21119 和被控端监听没有公网暴露。
8. UDP 会话数据和 IPv6 分别提供实际连接/抓包证据；未证明时保持未启用，不能用服务端 UDP 21116 的心跳或打洞包代替。

测试结果必须脱敏；真实公网地址、服务器 Key、设备 ID、Token 和原始抓包只保存在未跟踪的本地验收目录。
