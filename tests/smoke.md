### A. HomeDesk 默认 `lan_only` 回归

- [ ] `net.mode` 是唯一模式入口；未声明模式与旧 `pure_lan_default=true` 保持 `lan_only`，旧 `pure_lan_default=false` 不会隐式开启公网。
- [ ] 连接服务不可达且清空 DNS 缓存后运行不少于 10 分钟：抓包确认无 HomeDesk 发起的公网出站、外部服务 DNS、公共服务器回退、遥测或自动更新。
- [ ] M1–M7 按原家庭网络门禁回归，同网段 ID、IP 直连、局域网发现与内网中继行为无倒退。
- [ ] 断开互联网但保留局域网后，记录原纯内网 IP/发现兼容行为及真实加密状态；不能以原始 IP 连通代替加密验收，ID 服务不可达时不承诺按 ID 新建连接。

### B. HomeDesk `self_hosted` 配置与出站边界

- [ ] 只有构建默认或本机受控高级设置显式选择 `self_hosted`，并一次性通过模式、服务器、Key、来源和获准打洞选项校验后，才允许公网出站。
- [ ] 缺失、冲突或非法配置校验失败并提示原因，上一份有效配置保持不变；没有静默切换模式、安全回退或扩大权限。
- [ ] `lan_only` 与 `self_hosted` 的 {mode、server.host/key、家庭 CIDR/来源限制、打洞选项} 按模式原子保存且互不串用；构建 host/key 只初始化所选模式，未把一组自动复制给另一组。
- [ ] 切换目标模式的配置组缺失或非法时拒绝切换，当前 `net.mode` 与有效配置组保持不变；不完整配置不能部分生效。
- [ ] 抓包确认只访问自建公网 hbbs/hbbr、必要 DNS、经审核的打洞服务和当前连接需要的对端公网地址。
- [ ] 抓包确认未访问任何上游公共 RustDesk ID/API/中继、遥测或自动更新服务。
- [ ] UI 用中文显示“纯内网/自建公网”，并单独显示实际“直连/中继”和加密状态；网络模式不冒充连接结果，状态不只依赖颜色。
- [ ] 服务端 Key 校验生效；错误 Key 无法接入自建服务端，且不会回退公共服务器。
- [ ] 输入正确设备密码可连接，错误密码在被控端校验失败；服务端 Key 不能替代设备密码或授予远控权限。
- [ ] 错误/缺失服务器 Key、对端签名或 ID 不符及锁定版本非安全回退均被既有握手、配置或外围策略拒绝；若任一无法拒绝，公网发布门禁失败，不以新增签名协议绕过。
- [ ] 公网模式手输 IP/域名或仅返回 IP 的发现入口被拒绝并提示使用设备 ID；经服务器撮合的同网段 P2P 仍通过相同安全握手，不进入“继续非安全连接”。
- [ ] 公网模式没有原样套用家庭 CIDR 拒绝合法公网对端；配置显式来源限制后，限制外的直连和中继连接均被拒绝，设备认证仍不可绕过。
- [ ] 模式切换只有显式保存并重启客户端服务后才生效；重启时旧会话和上报队列已终止，未跨模式复用连接或凭据。

- [ ] 先用官方锁定客户端 + OSS `1.1.16` 验证，再用相同配置的 HomeDesk 定制包重复；两者结果分别记录。
